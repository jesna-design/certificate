# PROJECT: Secure Online Certificate Distribution Portal

## ROLE

Act as a senior full-stack web developer, UI/UX designer, and document-distribution system architect.

Develop a secure, simple, mobile-friendly web portal for distributing certificates to participants of the programme described in the attached programme document.

The attached programme document is the authoritative source for:
- Programme title
- Programme type
- Dates
- Organising institution
- Department
- Other relevant programme details

Do not invent programme details that are not available in the attachment.

---

# OBJECTIVE

I want to distribute TWO certificates to each participant through a single public HTTPS web link.

Each participant will have:
1. A registered email ID
2. A registered name
3. TWO individual certificate links

I will provide this participant information in a CSV file.

The system must allow a participant to:

1. Open the public HTTPS webpage.
2. Enter their registered email ID.
3. Submit the email ID.
4. The system searches the participant database.
5. If the email ID is valid, identify the corresponding participant.
6. Retrieve the TWO certificates associated with that participant.
7. Display the participant's registered name.
8. Display download buttons for both certificates.
9. Allow the participant to download both certificates individually.
10. Prevent access to certificates belonging to other participants.

---

# INPUT CSV

I will provide a CSV file containing participant information.

The CSV will contain columns similar to:

- Serial No.
- Registered Name
- Registered Email ID
- Certificate 1 Link
- Certificate 2 Link

The exact column names may vary.

Before building the system:

1. Read the CSV.
2. Identify the relevant columns automatically.
3. Validate every row.
4. Detect missing email IDs.
5. Detect missing certificate links.
6. Detect duplicate email IDs.
7. Detect duplicate participant names where relevant.
8. Detect invalid URLs.
9. Generate a validation report.
10. Do not silently discard any participant.

If duplicate email IDs exist, flag them clearly and require appropriate handling rather than randomly selecting one record.

# AUTHENTICATION / LOOKUP LOGIC

When the participant submits the email:

1. Normalize the email:
   - Trim whitespace.
   - Convert to lowercase for comparison.

2. Search the participant database.

3. If the email does not exist:

Display a friendly message:

"We could not find a participant record for this email ID. Please check that you have entered the same email ID used during registration."

Do not reveal whether similar email addresses exist.

4. If the email exists:

Display:

"Certificates available for: [Registered Name]"

Then display the two certificates separately.

- "Download Certificate"

### Certificate 2

- "View Certificate"
- "Download Certificate"

# DOWNLOAD FUNCTION

The participant must be able to download each certificate.

The system should provide clearly visible buttons:

[ View Certificate ]

[ Download Certificate ]

for each certificate.

The download should retrieve the exact certificate associated with that participant.

Do not allow the user to modify the certificate URL through the interface to access another participant's certificate.

---

# SECURITY REQUIREMENTS

This is an important requirement.

Do NOT expose the complete CSV file or participant database to the browser.

Do NOT place the entire participant database in JavaScript running on the client side.

The participant lookup must happen securely on the server/backend.

The frontend should only receive the minimum information required for the authenticated lookup.

Certificate links should not expose unnecessary participant information.

Implement reasonable protection against:

- SQL/NoSQL injection
- CSV injection
- XSS
- URL manipulation
- Enumeration of participant records
- Unauthorized access to other participants' certificates
- Malicious query parameters

Do not display the entire participant list anywhere on the website.

---

# EMAIL PRIVACY

Do not display the participant's complete email address after successful lookup unless necessary.

If displaying it, consider masking it, for example:

a****@gmail.com

The system must never display another participant's email address.

---

# MOBILE RESPONSIVENESS

The website must work properly on:

- Android phones
- iPhones
- Tablets
- Laptops
- Desktop computers

The email input and download buttons should be easy to use on mobile devices.

---

# ERROR HANDLING

Handle at least the following cases:

### Case 1 — Invalid email format

Display:

"Please enter a valid email address."

### Case 2 — Email not registered

Display:

"We could not find a participant record for this email ID. Please verify the email ID used during registration."

### Case 3 — Certificate 1 unavailable

Display an appropriate message and still provide Certificate 2 if available.

### Case 4 — Certificate 2 unavailable

Display an appropriate message and still provide Certificate 1 if available.

### Case 5 — Both certificates unavailable

Display:

"Your participant record was found, but your certificates are currently unavailable. Please contact the programme coordinator."

### Case 6 — Server/database error

Display a generic user-friendly error.

Do not expose technical error messages, database information, file paths, API keys, or server details.

REGISTERED EMAIL
        ↓
PARTICIPANT RECORD
        ↓

Participant B's email must ONLY return Participant B's two certificates.
